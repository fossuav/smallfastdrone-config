# ArduPilot Lua playbooks (vendored)

These files are the authoritative guides for writing the **Lua applets** that ship inside Lua-engine wizards (`src/wizards/<id>/applet.lua` — see [../WIZARDS.md](../WIZARDS.md)). When you write or modify an applet, read these first; they encode the API surface, the applet structure, and the safety rules that keep FC-side scripts correct and testable.

## Files

| File | Use for |
|---|---|
| [CLAUDE.md](CLAUDE.md) | Core Lua scripting guide — applet structure, `update()` scheduling, parameter tables, the module system, code-quality + safety rules. Start here. |
| [CLAUDE_VEHICLE_CONTROL.md](CLAUDE_VEHICLE_CONTROL.md) | Movement commands, controller behaviour, state/telemetry reads, RC input — for applets that command the vehicle. |
| [CLAUDE_CRSF_MENU.md](CLAUDE_CRSF_MENU.md) | CRSF (Crossfire/ELRS) transmitter-menu implementation via `crsf_helper.lua` — for the `crsf` wizard view (the field-operator surface). |
| [docs.lua](docs.lua) | **The API source of truth.** EmmyLua annotations for every ArduPilot Lua binding, generated by `./waf copter --scripting-docs`. Never invent a binding — if a signature is uncertain, it's in here. |

## Provenance — vendored, not original

These are copied **verbatim** from the ArduPilot AI Playbooks repo at <https://github.com/fossuav/aap> (`claude/libraries/AP_Scripting/` for the three `CLAUDE*.md` files, `lua/docs.lua` for the API reference). They are GPLv3, same as this project.

**Do not hand-edit them here** — that creates drift from upstream. If a guide needs a change, make it in `aap` and re-copy. To refresh:

```bash
cp ../aap/claude/libraries/AP_Scripting/CLAUDE.md              docs/lua/CLAUDE.md
cp ../aap/claude/libraries/AP_Scripting/CLAUDE_CRSF_MENU.md    docs/lua/
cp ../aap/claude/libraries/AP_Scripting/CLAUDE_VEHICLE_CONTROL.md docs/lua/
cp ../aap/lua/docs.lua                                          docs/lua/
```

`docs.lua` can also be regenerated from the firmware itself with `./waf copter --scripting-docs` in `vendor/smallfastdrone/`; refresh it after a submodule bump if you're relying on a new binding.

## What was deliberately left out

- **`AI_GIT_FORMAT_PATCH_PLAYBOOK.md`** — covers submitting Lua scripts back to ArduPilot via `git format-patch`. Our applets live in this repo (`src/wizards/`), they're not contributed upstream, so the workflow doesn't apply.
- **`digest-lua.txt`** — a 2.2 MB gitingest dump of the entire `AP_Scripting` tree for one-shot LLM ingestion. Redundant here: the real `AP_Scripting` source (applets, examples, modules) is already in the tree at `vendor/smallfastdrone/libraries/AP_Scripting/`, and the digest is regenerable. Not worth the repo bloat.

## Note on the `CLAUDE.md` filename

`docs/lua/CLAUDE.md` keeps its upstream name so the cross-references inside the other two guides ("see `CLAUDE.md`") stay valid. It is **not** auto-loaded as Claude Code project context — only the repo-root `CLAUDE.md` and the directory hierarchy of files being edited are. The discoverability hook for applet authoring is in [src/wizards/CLAUDE.md](../../src/wizards/CLAUDE.md), which points here.

Likewise, the guides reference `docs/docs.lua` (their path in the firmware tree); in this repo that file is `docs/lua/docs.lua`.
